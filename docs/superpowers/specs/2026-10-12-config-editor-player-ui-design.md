# 通用问答平台第二阶段：填写入口与玩家端设计

日期：2026-10-12
上位设计：`docs/superpowers/specs/2026-10-12-general-quiz-platform-design.md`

## 目标、范围与阶段边界

在第一阶段独立 `/v2` PostgreSQL 服务上交付真实可用的同源网页：组织者无需编辑 JSON 或调用 API，即可从空白创建、配置、预览并发布一场问答游戏；玩家通过专属链接报名、作答、获得持久化回执、查看已公布成绩。不同组织者、不同游戏继续严格隔离。所有默认界面、数据、文案和题库均不含旧活动品牌与预设内容。

本阶段交付四种自动判分题型、自定义报名字段、版本化草稿、错题作废和基础 NES.css 中文像素组件。抽奖与 16:9 大屏、完整视觉润色属于第三阶段；跨进程准入、实时状态分发、真实公网链路万人压测属于第四阶段。本阶段不宣称达到 10,000 人一秒提交、5 秒全员回执。旧应用和当前域名保持不变，不能把旧静态页面或未验收的新服务称为正式入口。

## 方案与模块

沿用 Node 原生 HTTP、浏览器 ES 模块及现有 PostgreSQL，不引入 React/Vite 或另一个后端。新服务自身在 `/` 提供组织者入口和登录，在 `/organizer` 提供游戏列表与创建/编辑/控制台，在 `/g/:slug` 提供玩家入口。静态文件由同一服务托管；管理页本身可以公开加载，但所有敏感数据和修改必须通过有权限的 `/v2` API 获取。HTML 永远不内嵌未公开题目的答案。

浏览器代码按组织者草稿、轮次/题目编辑、玩家注册/作答、提交状态和共享 API 客户端拆分为小模块；服务端按配置校验、版本写入、报名字段校验、四题型评分、错题更正和公开状态拆分。展示用户输入时只写 `textContent`/表单值，不解释成 HTML、CSS 或脚本。每个数据库写入都带 `game_id`，敏感资料仅授权管理端可见。

## 组织者创建与冻结

组织者登录后首先看到“创建游戏”而非任何预设项目。空白向导分五步：基本信息、报名字段、轮次与时长、题目与计分、预览与发布。可以返回任意步骤继续编辑，并明确提示是否已经同步到服务器。拥有 `owner` 权限者编辑与发布；可邀请已有平台组织者按 `operator` 权限操作本场开轮和查看控制台，但不能编辑题目或授权他人。平台管理员仍通过已有安全入口创建组织者账号，不开放匿名组织者自注册。

草稿保存采用全游戏递增版本号 `expectedVersion`：事务先锁游戏行，检查仍为 `draft` 且版本一致，再校验改动、写关系表及 `game_versions` 的完整快照，最后递增版本。旧版本请求返回 409 和当前版本；浏览器保留用户尚未保存的输入，提示加载最新配置后人工比对，不自动合并也不清空文本。轮次位置连续、题目位置连续。每场最多 20 轮，每轮最多 100 题；题目分值为 0–10,000 的整数，时长为 30 秒至 60 分钟。超出限制时在输入处和服务端同时明确报错。仅**已验证为本场 owner** 的单轮编辑接口允许最多 1 MiB 的 JSON 请求体，其余 API（特别是答卷）维持 64 KiB；发布前验证该轮所有可填写答案的最大 UTF-8 体积连同题号与 JSON 开销仍小于 64 KiB，否则要求组织者减少题数或字数上限。

发布是一次原子操作：检查至少一轮、每轮至少一题、全部题型规则有效、报名字段合法、页面预览可用；写入最终版本和发布状态。**发布后整场配置冻结**，包括标题、报名字段、题目、标准答案、分值、轮次顺序和时长。再次发布返回同一个已发布结果，不产生第二份配置；将来想举办另一场须新建游戏。邀请/撤销操作员和留痕错题作废属于运营动作，不修改冻结配置。已经由第一阶段发布的单选游戏继续可用，只读显示其原有配置；既有答卷与成绩不丢失。

### 配置接口

- `GET /v2/games/:gameId/editor`：仅成员可访问，返回草稿版本、完整题目及答案、字段配置、审计摘要；`operator` 只读。
- `PATCH /v2/games/:gameId/details`：`owner` 修改标题、介绍、报名字段和公开榜单选项，携带 `expectedVersion`。
- `PUT /v2/games/:gameId/rounds/:roundId` 与 `POST /v2/games/:gameId/rounds`：`owner` 在草稿期创建或覆盖单轮配置，携带 `expectedVersion`；采用每轮请求，不以整场超大 JSON 单次提交。草稿期删除/调整轮次时必须保持位置连续。
- `POST /v2/games/:gameId/publish`：`owner` 冻结并返回游戏链接与最终版本；沿用第一阶段手动开轮语义。
- `POST /v2/games/:gameId/members`：`owner` 按已有组织者登录名邀请本场 `operator`；重复邀请幂等，不授予跨游戏权限。
- `DELETE /v2/games/:gameId/members/:organizerId`：`owner` 撤销本场 `operator`，不可移除 `owner`；审计留痕，撤销后所有管理 API 立即重新校验成员身份。

所有编辑接口保留审计事件，包括操作者、旧/新版本、变更类型及时间。后台预览可以读取标准答案；玩家公开接口按状态过滤。

## 题型与评分

题目数据保存 `kind`、题干、分值、选项（如适用）及受校验的 `answer_rule_json`。使用追加 PostgreSQL 迁移放宽第一阶段 `questions` 的单选约束、增加报名字段与草稿表，并把现有 `correct_option` 转成相同语义的新规则；不改写既有迁移，不清除既有单选题或答卷。发布时保存规则版本；评分只采用该轮已冻结的规则。

| 题型 | 配置与玩家答案 | 自动判分 |
|---|---|---|
| 单选 `choice` | 2–6 个选项，唯一正确索引；玩家提交单个合法整数索引 | 完全相同得题目分值，否则 0 |
| 多选 `multiple` | 2–6 个选项，1 个以上正确索引；玩家提交去重的合法索引数组 | 集合完全相同得全分，否则 0；无部分分 |
| 标准答案填空 `exact` | 1–10 个非空可接受答案；玩家输入不超过 120 个 Unicode 码点的文本 | 两端先 `NFKC`、去首尾空白、统一 ASCII `A–Z` 的大小写；与任一答案完全一致得全分。**不忽略内部空格**、不做模糊/AI 判分 |
| 开放填写 `length` | 字数下限/上限由组织者配置，1–120 且下限不大于上限；玩家输入文本 | 去首尾空白后按 `Array.from(text).length` 计算 Unicode 码点数，满足区间得全分，不评价内容 |

空答案和未答题得 0 分，不倒扣。题目中直接说明标准答案规则或字数范围；判分在服务端，浏览器只做输入预检。公开中的轮次只返回题干、选项和所需的作答规则，不返回正确索引或可接受答案；结算并公布后才返回标准答案和个人分数。开放填写原文仅本人及本场授权组织者可见，不进公共榜单。

错题处理不篡改冻结题目：`owner` 在已公布轮次选择题目、填写原因，插入 `voided_questions(game_id,question_id,reason,actor_id,created_at)`；同一题不能重复作废。一个数据库事务中对受影响轮次全体玩家按现有答卷重算、更新成绩并记审计。已开始但未公布的错题由负责人等待结算后统一处理，不在作答期间偷改题干或答案。未来抽奖奖池冻结后由第三阶段阻止改分。

## 报名与玩家流程

展示名仍是每场玩家最低必填项，其余报名字段由组织者配置，最多 12 个，类型仅限短文本或有限选项；字段键使用安全的 ASCII 标识且彼此唯一，文本值最多 120 个 Unicode 码点，每个选项字段包含 2–20 个非空且去重的选项，标签与帮助文案限长。可按字段设置必填、文本长度或选项列表；真名不是默认必填。发布后的报名规则不变，注册时服务端使用该游戏的冻结版本验证并写入 `players.profile_json`。公开状态/榜单只显示展示名及消歧短 ID；自定义报名资料只在本场授权后台可见。

玩家用 `/g/:slug` 报名或以该场登录码和密码换设备登录，首次注册即自动登录；不同游戏可在同一浏览器保存各自会话。界面呈现等待、作答中、结算中和已公布状态。`GET /v2/games/:slug/state` 只返回服务端时间、公开报名说明、轮次/题数/时长/截止信息，不包含个人分数、报名资料、未开放题或正确答案；个人分数继续从登录后受保护的 `/my` 获取，公开榜单只显示已公布总分。组织者点击开始是唯一开轮触发，浏览器刷新或议程时间不触发开题。

答题时每次改动先保存本机草稿，服务端草稿保存限频（同一玩家/轮次最多每 15 秒一次自动请求，失焦和页面隐藏时可补一次）；`drafts` 通过 `(game_id,player_id,round_id)` 唯一键持久化，不能计分。刷新/换设备后恢复最新可信草稿和最后一次确认答卷，并清楚区分两者。本机临时内容和待确认的 `requestKey` 使用按游戏与玩家隔离的 `sessionStorage`，玩家退出时清除；跨设备依靠受保护的服务器草稿和答卷，不从其他账号的本机存储恢复。提交按钮生成并暂存 `requestKey` 与提交内容；服务端事务提交后才显示“提交成功”及回执编号。请求超时显示“未确认，可重试”，重试使用**同一键、同一内容**取回原回执；修改答案后生成新键。截止前可多次提交，以服务端最终成功版本为准；截止后新提交拒绝，已入库请求的同键重试仍返回原回执。作答期间排名只包含已公布轮次。

本场 `owner` 或 `operator` 可生成 10 分钟有效的一次性玩家恢复码，经人工身份核对交给本人；兑换时撤销该玩家在该游戏的旧会话，设置新密码并返回原账号。恢复码只保存哈希，仅本场授权者可生成；该操作和失败登录均受限流/审计，不用真名直接找回账号。

## 基础像素 UI 与中文

从本阶段引入 NES.css 的**固定版本自托管组件 CSS**，自定义布局和颜色变量，不复制其示例站点。界面视觉使用暖米色底、深墨蓝轮廓、橙红行动色和薄荷绿成功态；像素边框、硬阴影、关卡式步骤强调游戏感，但大面积表单保持清晰。自托管 Fusion Pixel Font 的 `12px + proportional + zh-Hans` WOFF2，用于短标题、菜单、按钮及计时/回执标签；长题干、解释、说明和开放填写输入回退常规中文字体。NES.css 与字体许可证分别随应用保存；不要把原活动标志、背景、文案带到新服务。

窄屏从 320px 起无横向滚动；390/768/1440px 均可完整创建、作答和恢复。触控按钮目标至少 44px，移动端输入字号避免浏览器意外放大；中文输入法组字过程中不触发自动交卷，键盘与屏幕阅读器可以操作，尊重 `prefers-reduced-motion`。字体或装饰加载失败时仍能看见计时、题目和提交回执。版本化静态资产设置长缓存，HTML 与 API 禁止缓存；前端初次加载的字体大小和缓存效果在第四阶段纳入实际网络压测。

## 故障、测试与交付标准

版本冲突返回 409 与服务器当前版本，浏览器保留本地输入供人工比较；字段或题目校验返回明确的字段路径及错误消息，不把 SQL/堆栈给玩家。断网、超时、数据库不可用均显示“未确认”，不伪造成功。多名组织者同时发布时只会形成一个冻结版本；跨游戏猜测游戏/玩家/题目/恢复码 ID 必须被拒绝。启动后从现有 PostgreSQL 迁移并保留第一阶段的游戏和答卷，旧 SQLite 仍只留单独存档，生产数据与测试数据不能混用。

自动化测试覆盖四题型的正常值、空值、边界和特殊 Unicode；并发编辑/发布与发布冻结；跨场权限；未公布答案不泄露；草稿与正式交卷隔离；断线后幂等回执；错题作废全体重算；玩家恢复码一次性和跨场拒绝。浏览器验收至少覆盖手机 320/390px、平板 768px、桌面 1440px、中文输入法、键盘操作、屏幕阅读器标签和字体失败回退。保留原应用的测试与启动命令，新服务在自己的端口提供可用网页和 `/v2` API。第三、四阶段的抽奖、大屏及万人性能不能被第二阶段的功能测试替代。
