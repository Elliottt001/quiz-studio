# 现场操作手册

> 若使用校网 Linux 服务器长期运行并以既有域名作为统一入口，以[校网服务器部署说明](/Users/bytedance/Projects/xlab-annual-quiz/docs/campus-server-deploy.md)为启动、HTTPS、DNS 步骤；下文第 2 节是旧的现场主机直连 TLS 方案，不应与 systemd + Nginx 的配置混用。

适用范围：2026 年 10 月 11 日 X-Lab 年度大会。本文件是本地 Web 应用的运行说明，不替代[游戏策划案](/Users/bytedance/Documents/X-Lab年会答题游戏策划案-定稿.md)、总议程和奖品执行单。

## 1. 会前必须到位

- 专用主机和备用电脑各一台，检查操作系统均能运行 Node.js 24.19.0+、剩余磁盘空间、电源与休眠设置。软件自检成功不等于校网可用。
- 校网允许约 200 部手机访问主机的内网 IP，不隔离客户端；主机 IP 稳定。用至少两部真实手机（含微信内置浏览器）在会场测试实际域名。连蜂窝网络的人无法访问局域网主机。
- 使用受信任的域名与有效 HTTPS 证书；可以用域名 DNS 验证方式取得证书，但仍须让校网内 DNS 将域名解析到主机的内网 IP。证书域名与玩家链接一致，私钥只留在主机且限操作员访问。**不绕过手机浏览器的证书安全警告。**
- 张瑞喆落实管理员及后台操作员；正式分享材料与参会账号权限核验后导入 30 题；李佳懿填写真实奖品名称、数量、颁奖人和补领方式。人数未知时不预设奖品数量。
- 原始主视觉保存在 `design/`，玩家与投屏只使用 `public/brand/` 中已裁掉地点占位内容的素材。

## 2. 启动配置

打开项目根目录，运行 `node --version`，确认主机具备 Node.js 24.19.0+。没有 npm 包下载步骤。运行 `node scripts/admin-password.mjs`；口令至少 16 字符，脚本在交互终端隐藏输入，输出一行哈希。只把哈希放进项目根目录的 `.env.local`：

```text
HOST=0.0.0.0
PORT=4173
ADMIN_PASSWORD_HASH=这里粘贴生成的哈希
TLS_CERT_PATH=/绝对路径/fullchain.pem
TLS_KEY_PATH=/绝对路径/privkey.pem
```

路径用**现场主机**可读取的真实绝对路径。`.env.local` 和 `data/` 已被 Git 忽略，不上传 GitHub。不要把管理员口令或私钥发到微信群。正式启动前执行：

```bash
npm test
npm run check
npm run build
npm start
```

`npm start` 读取 `.env.local`，在现场网卡上监听 HTTPS；若没有证书、私钥或管理员哈希，非回环监听应失败。用手机访问 `https://你的域名:4173/`，将这一**实际验证可用的域名链接**发微信群；给操作员单独提供 `/admin.html`，大屏使用 `/display.html`。不应把终端中显示的 `0.0.0.0` 或本机 `127.0.0.1` 发给玩家。校网禁用 4173 端口时，须经网络负责人同意调整允许的端口并重新验收；不要临时暴露管理端到公网。

## 3. 彩排与正式操作

1. **彩排前：** 先确认正式数据库是否有真实数据。不要在正式房间用演示题、测试账号或假奖品演练；可复制程序到独立目录、使用独立 `data/` 做完整测试。确认题库导入仅用真实审核稿，全部 30 题与来源一致。
2. **签到阶段：** 杨欣月分发链接及校网说明，玩家填写真名、昵称、2019–2025 级及四团队之一，注册后即自动登录。可在大厅答不计分练习题。后台检查同名同年级同团队的疑似重复账号，不自动合并；明确重复或题库／后台人员需在锁池前排除。
3. **开轮：** 操作员先确认嘉宾分享结束、题库数量正确，点击后台唯一的“开始第 N 轮”。**议程时钟不触发开题**，网页和后台刷新也不触发。服务器以点击成功时刻计满 300 秒；大屏显示倒计时，最后一秒集中提交须出现“提交成功”回执。作答中排行榜只显示此前已公布轮次。
4. **收卷：** 到实际开题后 300 秒，服务器自动拒绝新提交、结算已确认答卷并更新手机排名，无须再点“截止”。若后台显示“结算中”，先核对数据库和提交数量，不手工改总分。大屏按导演指令切回分享／仪式页面，不等待每题讲评。
5. **核分：** 后台登记分享／工作 +10，个人额外最多 20；对无效题使用全员作废，理由和操作记录留存。最后一轮结束到抽奖前，处理迟报、错题、资格排除与奖品核对。成功交过至少一轮的账号可进入**待中奖核验**奖池；工作人员因任务未作答需显式登记工作资格。**不要求 200 人在抽奖前逐个签到勾选。**
6. **冻结和抽奖：** 确认奖品数量不超过合资格人数、规则无未决申诉，点击“冻结奖池”。系统给每人 `10 + 总分 / 10` 颗虚拟球（整场无有效答题时，每名未排除注册玩家一颗）。依次抽三等奖、二等奖、大奖，每次用当前剩余球池。点击抽奖前确认投屏状态；结果先持久化、再动画展示。每次中奖时核对本人及所属账号；无资格或放弃要记录理由，公开补抽，原人仍退出后续奖项。
7. **结束：** 在后台下载核分与抽奖 JSON，文件含真名、答卷和操作日志，限授权人员保管；核对奖品领取表，按大会政策清理不再需要的个人数据。大屏 16:20 前交还合照，不能为了动画占用合照时段。

## 4. 备份与恢复

正式数据库位于 `data/game.sqlite`，会在当前登录账户下设置为私有权限；系统在每轮收卷、最终冻结、抽取及关键更正后生成一致性备份 `data/backup-latest.sqlite`。不要在 SQLite WAL 运行期间仅复制 `game.sqlite` 单文件，可能漏掉尚在 WAL 内的数据。

可在本机检查快照：

```bash
node scripts/backup-check.mjs data/backup-latest.sqlite
```

它显示完整性、玩家／答卷／成绩数量、冻结哈希、中奖数和四轮截止时刻。每轮结束及冻结后，把**已经生成并检查完整的快照**转交备用电脑的受保护目录；若不能转交，单主机硬件损坏会同时丢失主库与本机备份。备用电脑恢复时先停止主机服务，在备用电脑安全目录中把最近完整快照作为 `data/game.sqlite` 使用，启动同一版本程序，核对恢复报告、管理员、轮次状态、已中奖名单，并统一通知新的 HTTPS 地址。若域名仍指向故障主机，须先更新校网 DNS 后再宣布恢复，不能仅换电脑就让旧链接“自动可用”。

## 5. 测试与发布门槛

`npm test` 检查身份、计时、交卷、错题重算、球池、抽奖、界面资源、备份和隐私边界；`npm run check` 检查服务器与页面脚本语法；`npm run build` 准备静态文件。以下脚本**只使用临时数据库**，不接触正式房间：

```bash
node scripts/load-test.mjs --clients 300 --last-second-submits 200
```

脚本并行注册 300 人，让其中 200 人在模拟轮次截止前的**真实流逝一秒窗口**交卷，报告实际耗时、接收数、迟到拒收、唯一成绩数和 p95 延迟。它验证当前电脑回环请求，不等于现场 200 部手机连校网测试。正式发布前，在实际主机、校网、微信和大屏上复测这五项：HTTPS 无警告可打开、同设备登录与换设备恢复、最后一秒交卷、主备数据库恢复、真实奖品数量在十分钟内领取完。任一关键项未通过，不称作“零异常”或“已上线”。

## 6. 故障处理

- 个别手机断线：回到同一链接，保持原账号；未得到“提交成功”回执的草稿不视为交卷，不为个别人延时。
- 校网整体故障：保留已经确认的交卷记录，无法保证同轮公平时统一取消该轮；不能让少数仍能联网的人独占分数。恢复后公布统一处理结果。
- 服务器进程重启：数据库保留实际开始与截止时刻；过期轮次自动结算，不重新开放五分钟。先核验抽奖和成绩，再继续。
- 主机硬件故障：按第 4 节从最近完整备份恢复；缺少可信快照时暂停后续抽奖，明确说明后续安排，不手工指定中奖者。
- 题目实质错误：后台填写原因作废该题，所有人的该题分数统一归零并重算；奖池冻结后暂停新增操作，交总负责人公开处置。
- 抽奖画面中断：先检查已保存记录；有记录就沿用原球号和中奖者，不因动画卡住而重抽。确认身份后标记领取；明确放弃才按规则公开补抽。

所有异常决定由游戏负责人和总流程负责人协调，后台留下操作者、时间和原因；控制台的“作废”并不是用于随意挽回时间的快捷按钮。
