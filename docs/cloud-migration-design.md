# Public full-game migration design (2026-10-08)

**Objective:** `https://x-lab.game.elliotttzhang.cn/` serves the actual player, operator, display, and `/api` routes from one public HTTPS origin, accessible on phones and any personal/shared computer. GitHub stores source and triggers deployment; GitHub Pages cannot run the Node/SQLite backend.

**Hosting choice:** A single managed Node web service with an attached persistent disk. Use Render Blueprint as a deployable default; the service owner must connect the GitHub repository and enable paid web/disk resources. Keep SQLite on the mounted volume and one service instance. This minimizes migration risk before October 11. Backups must be copied off-host before live use; two files on one disk are not independent backups.

**Identity:** At registration, require real name, nickname, grade, team, and a self-chosen password. Assign an immutable, unique, readable login code; it and the password log in to the same account on any computer. Admin credentials remain separate. Every user can log out; logout revokes their own session and clears the cookie. On a shared computer, the next player must log out before switching accounts. Existing pre-migration accounts without passwords retain their data but require staff-assisted recovery to set credentials; do not silently expose them by name lookup.

**Security:** Store only salted scrypt password hashes and token hashes. Rate-limit login attempts without blocking all students behind one address. Set `Secure; HttpOnly; SameSite=Strict` cookies on the public domain; validate an exact HTTPS Origin for state-changing requests. Trust TLS termination only when explicitly configured for the managed service, not an arbitrary `X-Forwarded-*` header. There is no direct public SQLite file access.

**Runtime:** `DATA_DIR` points to the persistent mount; the Node process listens on the platform `PORT`/`0.0.0.0`. The managed HTTPS proxy is the public boundary. Auto-close remains based solely on the admin's actual start time +300 seconds; all scoring, ranking, pool freeze, and draws remain server-authoritative. One instance and a single SQLite writer are deliberate constraints; run an end-to-end load test against a staging deployment, not the production event room.

**Deployment:** Add a Blueprint, smoke tests, environment example, and runbook. Create a managed service from this repository, verify its temporary platform URL, add `x-lab.game.elliotttzhang.cn` as a custom domain, replace the Volcengine CNAME with the provider-assigned target only after readiness, verify HTTPS and full API, then disable/remove the old Pages custom-domain binding. Until the cloud service exists, do not change the live DNS.

**Acceptance:** Two users register/log in/out/in across separate browsers; the same login code cannot open the admin console; four rounds start only by admin click and auto-settle at 300 seconds; published-only rankings; weighted draws persist after restart; `/api/health` and content at the custom domain share the same origin; 300 connections/200 final-second submissions on the chosen tier; storage survives redeploy. Missing service credentials, DNS access, payment, prize list, or question bank are explicit launch blockers.
